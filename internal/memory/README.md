# 跨会话记忆（长期记忆）方案设计

> 本文件保留最初的问题和需求草稿。已收敛的完整架构、数据模型、流程、错误处理、测试和实施阶段见 [DESIGN.md](./DESIGN.md)。

当前实现状态：会话 Transcript 的有效前缀恢复、`AGENTS.md`/`RULES.md` 安全加载、文件型 RawMemory/租约/Snapshot Store、Phase 1 抽取、Phase 2 确定性或 LLM 整合，以及 ContextManager 的长期记忆注入已经落地。终端 `/memory` 管理命令、Session 软删除和自动清理仍未接入运行时。

首先提出几个问题：
1. 需要什么样的长期记忆？
2. 何时进行记忆存储？
3. 怎么加载长期记忆？

## 长期记忆分类
1. 会话的持久化
    和Agent的每次对话都保存下来
2. 项目知识
    预先写好的项目知识和编码规范
3. 自动记忆
    Agent在对话中自动积累的经验（编码习惯，项目技术细节等）

## 会话的持久化
对用户输入，模型输出，工具调用及调用结果都进行持久化保存
下一次打开会话时完全恢复现场
存储格式：消息角色，完整内容，时间戳
存储文件路径：.ffcode/sessions/session-20260726-145100-achf.json (session-日期-时间-随机尾缀)
写入顺序（写入文件和写入内存同时进行）

会话恢复：
1. 逐行解析json，遇到失败的跳过
2. 验证消息完整性
    截断到最后一个所有工具都输出的位置
3. 插入时间跨度提示
    避免代码或文件变更，导致agent拿着过期文件

会话请求：
清理超过30天未活跃的对话


## 项目知识
预先写好的项目知识和编码规范
1. 项目知识
    通过 AGENG.md 保存
2. 编码规范
    通过 RULES.md 保存
在文件中支持@include指令，但禁止循环嵌套

## 自动记忆
### 要提取的四类记忆
1. 用户偏好
2. 纠正反馈
3. 项目知识
4. 参考信息
### 存储目录
.ffcode/memory/
记忆去重
每一轮loop结束后启动后台线程提取
